# Glide 运维运行手册

## 1. 运行目标

Glide 是无服务端、本地优先的桌面应用。可运维性目标是：

- 应用重启后可直接读取后台管理密码，不出现电脑密码弹窗；
- 工作区、凭据、诊断三类数据相互隔离；
- 云端写入必须经过计划预览和最终确认；
- 单条线路故障不能阻塞其他线路超过 12 秒；
- 任何错误不得把密码、Token、订阅或完整管理地址写入日志。

## 2. 本地数据边界

| 数据 | 位置 | 恢复要求 |
| --- | --- | --- |
| 工作区 | Tauri AppData 下的 `glide.db` | 可从线路资料重新导入 |
| 后台密码 | AppData 下的 `credentials/credentials.db` | 必须与 `master-key.v1` 成对备份 |
| 凭据密钥 | AppData 下的 `credentials/master-key.v1` | 丢失后不能从密文恢复 |
| Cloudflare Token | 仅当前进程内存 | 退出后重新授权 |
| 脱敏诊断 | `glide.db` | 可安全清除 |

macOS/Linux 凭据目录权限应为 `0700`，数据库和密钥应为 `0600`。Windows 文件继承
当前用户 AppData ACL。禁止只备份数据库而不备份密钥，也禁止把凭据目录上传到 Issue、
聊天、网盘或公开仓库。

## 3. 启动检查

1. 版本、操作系统和架构在“设置”底部正确显示。
2. “检查 → 运行快速检查”中的“本机凭据目录”必须为通过或可操作的缺失提示。
3. 第一次从旧版升级时，在 Glide 内输入一次 VPN 后台密码；不应出现系统 Keychain、
   Credential Manager 或电脑密码弹窗。
4. 退出并重新打开 Glide，再执行“一键优化线路”；应直接读取本地凭据。
5. 工作区保存状态应从“正在保存”恢复为“本地数据已保护”。

## 4. 故障与恢复

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| 凭据目录无法读取 | 磁盘满、权限变化、文件损坏 | 先检查可用空间和目录权限；不要删除密钥 |
| 提示缺少管理密码 | 首次升级、线路引用新增 | 在 Glide 内补录一次后台密码 |
| 主密文完整性失败 | 非正常写入或文件篡改 | Glide 自动尝试上一版密文；随后逐条验证线路 |
| 密钥缺失或格式无效 | 文件被移走或损坏 | 从同一次备份恢复密钥和数据库；否则重新录入密码 |
| 创建失败并回滚不完整 | Cloudflare API 中断或配额变化 | 到控制台检查 `glide-` 前缀 Worker/KV，不删除其他资源 |
| `workers.dev` 无法访问 | 当前网络限制或 Cloudflare 路径异常 | 不反复重建；换网络验证或使用已合规配置的自定义域名 |
| Windows/macOS 安装警告 | 未完成可信签名或公证 | 预览版只用于受控测试；正式发布前完成平台签名 |

不要通过删除整个 AppData 目录“修复”单一问题。删除凭据密钥会永久失去本机密文的恢复
能力；删除工作区不会删除 Cloudflare 资源。

## 5. 发布闸门

每个候选版本必须完成：

1. `npm ci`、前端覆盖率、发布工具测试和生产构建；
2. Rust 全部测试、格式检查和 `-D warnings` 严格 Clippy；
3. npm audit、RustSec、秘密扫描和许可证检查；
4. macOS 与 Windows 各自产出安装包和 `SHA256SUMS.txt`；
5. 新用户、旧版升级、退出重启、磁盘空间不足、凭据损坏、取消创建和失败回滚测试；
6. macOS Developer ID/公证与 Windows 可信签名；
7. 用户本人 Cloudflare 账号的短期 Token 创建验收；
8. 法律、Cloudflare 用途和宣传语审查。

任何一项未完成时只能标记为 Preview，不得宣称“保证中国大陆稳定直连”。

0.6.1 当前已通过前端 66 项、Rust 50 项（含仅监听 `127.0.0.1` 的 Cloudflare API、
OAuth 和凭据库测试）和发布工具 2 项测试。真实账号的三线路创建仍必须在发布闸门中
单独记录结果，模拟测试不能替代。

## 7. 2026-07-30 现场回归

- 五条已保存线路再次运行真实一键优化；一次从五条全部成功的结果选择线路 5，另一次
  在三条线路临时失败时从两条成功线路中选择线路 2，证明选择取决于本轮结果而非固定
  日本线路。
- 一键优化返回 10 个真实订阅节点；在透明代理环境下检测到不可信的 1 ms TCP 结果，
  最终构建改为“入口延迟不可测”，不把代理截获耗时冒充节点速度。
- 在已选择线路 2 的订阅中点击“美国”，应用自动切到本轮包含美国标签且响应更优的
  线路 5；不要求重新输入后台密码。
- 选择单节点后同时保留“复制整条订阅、订阅二维码、复制当前节点、节点二维码”四个
  入口。真实回归未点击复制或展示二维码，避免把订阅秘密写入剪贴板或测试证据。
- 创建页面正确识别当前包未配置发布者 OAuth Client，禁用一键登录并自动展示最小权限
  Token 兜底；OAuth 网络授权需待公共 Client ID 配置后验收。

## 8. 事件响应

- 凭据疑似泄露：先在远端管理后台轮换密码和订阅身份，再删除 Glide 本机记录。
- Cloudflare Token 疑似泄露：立即在 Cloudflare 控制台撤销，不等待本机清理。
- Release 校验不一致：停止分发、撤下对应 Release、检查 CI 和账号访问记录并重新签名。
- 上游 Worker 提交或哈希变化：停止自动创建，完成源码、许可和行为审查后再更新固定值。
- 不收集默认遥测。排障证据只能由用户主动导出脱敏结果，禁止索取完整凭据目录。
