# Glide 专业操作与发布规范

## 1. 连接资料生命周期

### 1.1 导入前

1. 线路名称保持唯一、可识别，最多 64 个字符。
2. 管理入口必须是公开域名的 HTTPS 地址，并明确指向 `/admin`。
3. 地址不得包含用户名、密码、查询参数或片段。
4. 同一管理入口只允许导入一次。
5. 管理密码只在当前表单内短暂存在，不进入日志、诊断或工作区数据库。

### 1.2 只读检查

1. 前端先做格式、长度和重复检查。
2. 桌面端重新解析地址并执行 DNS 检查。
3. DNS 结果包含本机、私网、文档或未知保留网段时立即停止；标准
   `198.18.0.0/15` Fake-IP 仅用于建立 TLS 连接，原始域名证书验证通过前不发送密码。
4. HTTP 重定向不自动跟随，避免跳转到未验证目标。
5. 向 `/login` 提交管理员密码，只接受格式严格的认证 Cookie。
6. 使用同一 User-Agent 和认证 Cookie 读取 `/admin/config.json`，响应上限为 1 MiB。
7. 配置必须包含节点域名、UUID 和路径；返回前只保留统计、状态和不可逆短指纹。

### 1.3 保存

1. 通过真实登录和配置读取后才显示最终确认页。
2. 管理密码写入 Glide 专属本机凭据目录中的加密数据库；应用直接读取，不请求电脑
   登录密码或创建逐线路系统授权项。
3. 工作区只保存随机凭据引用和脱敏地址标签。
4. 新线路初始为“待验证”，首次诊断后才更新健康状态。
5. 旧线路缺少地址或凭据引用时，可在管理弹窗中原地补录并迁移，不需要先删除。

### 1.4 删除

1. 删除操作必须再次确认。
2. 先从 Glide 加密凭据数据库删除对应密码，再删除本机线路记录。
3. 本地凭据事务失败时保留线路记录并提示重试。
4. 本机删除不会修改远端服务器；远端泄露仍需服务端轮换。

## 2. 诊断与健康度

1. 相同管理入口在一次诊断中只检查一次。
2. 每批最多检查 20 个入口，单次最多 100 个，避免误触发流量或风控。
3. 诊断结果只保存脱敏入口、状态、耗时和可操作说明。
4. 健康度只表示管理入口的近期可达性，不代表出口国家、吞吐量或长期稳定性。
5. 国家地区必须由至少两个独立证据源一致确认后，才能标记为“已验证”。
6. 深度吞吐测试必须由用户主动触发，不能后台静默运行。
7. 不同域名若返回相同 UUID 或节点路径，必须标记为同一故障域。

## 2A. Cloudflare 创建

1. 用户账号密码只填写在 Cloudflare 官方系统浏览器页面；Glide 首选 OAuth + S256
   PKCE，不读取账号密码。
2. 发行包没有已审核 OAuth Client ID 时才展示高级最小权限 API Token；禁止 Global
   API Key，手动 Token 建议设置 1 天有效期。
3. 授权阶段只读取账号列表，创建前显示公共子域、KV、Worker 和入口的完整计划。
4. 用户点击最终确认前不创建任何云端资源。
5. 上游载荷必须固定提交、限制大小并通过 SHA-256 后，才能开始云端写入。
6. 同名资源没有本机凭据、或 Worker 与 KV 状态不一致时必须停止，不自动覆盖。
7. 失败时只回滚本次创建的资源；已有资源不得因回滚被删除。
8. 只有真实登录管理页、读取配置、生成并读取订阅全部通过后，才能加入连接组。
9. OAuth access token 或高级 Token 只进入当前创建页面的进程内存；允许连续创建
   多条线路，完成或取消时只
   删除一次，离开页面或退出时由卸载清理兜底销毁，并提示用户按有效期或在官方
   控制台撤销服务端 Token。
10. OAuth 必须校验随机 state、S256 verifier、固定回环路径、来源和 5 分钟截止；
    Client ID 可以公开，应用内不得包含 Client secret。

## 3. 线路选择、节点选择与一键优化

1. 一键优化线路必须由用户主动触发，不允许后台静默登录全部管理入口。
2. Worker、管理后台或服务器入口统一称为“线路”；订阅中的 VLESS、Trojan 或
   Shadowsocks URI 才称为“节点”，UI 不得混用。
3. 线路验证后才能读取节点；节点列表不得把完整 URI、UUID、密码或主机名写入工作区。
4. 节点标签区域仅按备注识别，界面不得称为“目标区域”或“真实出口”；未匹配节点显示
   “未识别”，实际出口必须由客户端连接后独立验收。
5. 仅使用 Glide 本机加密目录中的现有后台密码执行只读探针，不修改任何远端配置，
   不触发电脑密码弹窗。
6. 无管理地址、无凭据、读取失败或订阅不可用的线路不得进入自动候选集。
7. 线路排序综合复测后的典型响应、波动惩罚、健康度、凭据风险与订阅状态；不能只
   选择单次延迟最低项，节点区域偏好也不得错误改变线路排序。
8. 手动选择先验证真实订阅；工作区只保存线路 ID、模式、理由和时间，订阅本身不落盘。
9. 删除当前首选线路后必须清除失效选择，不允许指向不存在的线路。
10. 单轮探针在一次认证会话中完成配置读取与订阅验证；最多同时探测 4 条线路，防止
   大连接组同时压垮后台。
11. 成功结果必须提供整条线路订阅复制、按标签选择节点和临时二维码，不得只写入首选
    线路 ID。
12. Glide 不得表述为已经切换第三方客户端流量；复制或扫码后仍由用户在客户端导入。
13. 全部刷新失败时保留原选择并展示修复提示，不进行静默回退或随机切换。
14. 单条优化探针必须有明确截止时间；慢线路不得无限拖住整次优化。
15. 小型连接组对全部可用候选执行第二轮验证；大型连接组至少复测前 8 名及当前自动
    线路，并将中位响应、波动和复测失败惩罚纳入排序。
16. 用户主动点击“一键优化”必须采用本轮综合第一，不得因上次选中线路而保留第二名；
    后台自动切换功能若未来加入，才可单独使用防抖容差。
17. 只要存在完成两轮验证的候选，单轮候选不得成为自动首选；只有全部候选均无法复测
    时才允许使用单轮结果，并在界面保持降级表述。
18. 选择单个节点时必须重新读取最新订阅并按哈希标识匹配；节点已消失时要求重新选择，
    不使用内存中的旧 URI。
19. 优化时可探测订阅中去重后的公开节点入口；全应用最多并发 16 路、单次握手
    2.5 秒、每条线路最多 64 个目标且总预算 15 秒。TLS 节点必须使用订阅中的 SNI
    完成证书校验和响应头握手，取三次中位数并显示波动；Fake-IP 时只向固定可信 DNS
    发送节点域名。普通 TCP 的 0–4 ms 本机接管结果必须标为“被本机代理接管”，不能
    冒充真实延迟。所有结果仍只称“入口延迟”，不得冒充带宽或完整代理隧道延迟。
20. 选择单节点后必须继续保留整条订阅，复制和二维码分别提供“整条订阅”和“当前节点”
    两组动作，不能互相覆盖。

## 4. 订阅输出

1. 订阅必须使用公开域名的 HTTPS 地址。
2. 订阅必须从已认证后台配置生成，不能让用户重复粘贴与当前线路无关的地址。
3. 订阅原文不进入工作区；二维码只在当前窗口短暂显示。
4. URL 必须固定 `target=mixed`，不得因客户端 User-Agent 自动调用第三方转换服务。
5. 需要客户端专有配置格式时必须在本地转换，或明确取得用户同意后使用第三方服务；
   当前版本不做后台第三方转换。
6. 剪贴板可能被系统同步或历史工具读取；导入后应立即清空。
7. 删除 Glide 本机记录不等于撤销服务端订阅。

## 5. 客户端下载

1. 只打开项目维护者的官方 GitHub Releases 页面。
2. 用户必须按操作系统和 CPU 架构选择安装包。
3. 正式分发必须提供签名、SHA-256 和发布说明。
4. 未签名 Windows 包只作为 CI 测试工件，不面向普通用户发布。
5. 未完成 Apple Developer ID 签名和公证的 macOS 包必须标记为预览版。

## 6. 本地隐私边界

允许保存在本机工作区：

- 线路显示名称和配置地区
- 管理入口完整地址
- 随机凭据引用
- 脱敏诊断结果

禁止进入工作区、日志和遥测：

- 管理密码
- 订阅原文
- API Key、Token 和全局密钥
- 用户浏览历史
- 可跨设备识别用户的持久标识

## 7. GitHub 发布闸门

每次发布前必须全部满足：

- 前端测试、覆盖率、生产构建通过
- Rust 测试、格式和严格 Clippy 通过
- 生产依赖审计无高危漏洞
- 源码敏感信息扫描无命中
- macOS 与 Windows CI 构建通过
- Release 附带 SHA-256 校验文件
- Release 明确平台、架构、签名和已知限制
- Secret Scanning、Push Protection、Dependabot 安全更新保持启用

## 8. 参考实现

流程设计参考了以下成熟开源项目的公开做法，但 Glide 不复制其代理核心：

- [Hiddify App](https://github.com/hiddify/hiddify-app)：重复配置防护、配置验证、HTTPS 订阅和设备端体验
- [Mihomo healthcheck.go](https://github.com/MetaCubeX/mihomo/blob/Meta/adapter/provider/healthcheck.go)：
  通过代理访问测试 URL、健康检查超时、受控并发和按测试 URL 保存结果
- [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev)：安全草稿更新、
  配置验证、重试回退、错误脱敏和跨平台发布
- [v2rayN SpeedtestService.cs](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Services/SpeedtestService.cs)：
  区分 TCPing 与真实代理 Ping、测速分批、并发限制和失败项缩小批次复测
- [Tauri](https://github.com/tauri-apps/tauri)：能力白名单、CSP、签名和桌面 IPC 安全边界

这里只复用公开的工程思想。Glide 的实现为独立编写，不复制 GPL 项目的源码；项目正式
公开前仍须由维护者选择并确认 Glide 自身许可证。
